# Leo 8.2 — Dashboard and upload repair

The dashboard now has a navy profit card, warm scheduled-work card, four readable financial totals, a compact receipt/document entry, open-work agenda, navigation shortcuts and recent activity. General businesses get invoice/bill views; trucking companies retain scheduled/earned load distinctions. Reporting formulas remain the existing domain functions. The layout was checked at desktop and 390px phone width, including drawer navigation.

## Upload and receipt changes
- Includes the previously unpublished 8.1 receipt fix: MM/DD/YYYY dates, retail receipt detection despite Invoice Number labels, reviewed fuel/expense drafts and original-photo attachment. Missing/disputed information stays editable and requires review. Long receipt images are enlarged and read with two OCR layouts; receipt totals are never inferred from rewards points or barcodes. When a Total label is missed, a received card/cash amount is used only if an independent subtotal agrees, with a printed-total review warning.
- Canonical MIME types come from file signatures, fixing missing/mistyped camera MIME labels. Invalid formats get an actionable export message. HEIC/HEIF is not supported. JPG/PNG/WebP photos above 6MB are optimized to a JPEG copy; PDFs must remain under 10MB. The file selector accepts a photo up to 40MB for optimization, and uploaded files stay within the existing 10MB private bucket limit.
- Upload forms and asynchronous preparation remain bound to the original account/company. Saved image documents now offer Read photo through an authorized, short-lived URL. Known linked photos show their existing record instead of another expense draft.
- Server upload IDs and paths depend on company, uploader, record and file content. Repeating a request returns the existing file. Storage is never overwritten; metadata-insert retries recover from already-uploaded bytes. No new table, policy, bucket or permission is needed.
- Fuel gallons and price per gallon retain three decimal places; monetary totals retain cents. This does not rewrite existing records.

## Validation
80 Node tests pass: finance totals, invoice/bill installments, photo matching, receipt parsing, MIME recovery, fuel precision, upload ID scoping, actual Edge handler retry/metadata failure, and company change during preparation/download. Browser checks used an isolated synthetic company, with local OCR of the two supplied private receipts, receipt draft/save/photo attachment, saved-photo review/duplicate detection, general-business layout, 390px navigation and a large synthetic image optimized to approximately 2.4MB. The HTTP preview uses a test-only digest adapter; production HTTPS uses native SHA-256. No private photos or raw OCR text are included in source or the public repository.

Server function leos-platform v7 contains the retry/precision fixes. Static assets use 82 filenames to avoid stale browser module caches. Payment confirmation, tenant roles and receipt storage remain private. OCR still requires review; card charging, bank verification, refunds, PDF OCR and offline uploads are not enabled. The separate personal toolkit is preserved.
